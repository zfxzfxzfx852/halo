## 二、已知限制（诚实披露，写入 SECURITY/文档）

1. **沙箱驱动**：当前仅实现进程级（process）驱动；Docker、gVisor、Firecracker、WASM 为预留接口，调用返回 `ErrNotImplemented`，将在后续版本落地。
2. **Windows**：暂无原生支持，建议通过 Docker 或 WSL 运行。
3. **防护边界**：Halo 不防御其信任边界之外的威胁（如宿主已被攻破、内核级攻击），详见 `docs/SECURITY.md`。
4. **Homebrew formula**：发布时需在 Release 产物就绪后回填校验值。
5. **前端产物**：`web/dist` 不入库，由 CI/发布流程构建并嵌入。

## 三、反馈分级与处理

| 级别 | 定义 | 处理时限 |
|---|---|---|
| P0 阻塞 | 无法安装/启动、数据损坏、安全漏洞 | 发布前必须修复，否则延期 |
| P1 严重 | 核心功能错误、审计/检测失效 | 发布前修复或明确规避方案 |
| P2 一般 | 非核心 bug、体验问题 | 记录，排期 v1.0.1 |
| P3 建议 | 功能增强、新适配器请求 | 进入需求池，按呼声排序 |

反馈统一收敛到 GitHub Issues，按模板归类；安全问题走 `SECURITY.md` 私密披露，不在公开 issue 讨论。

## 四、发布门槛（Go/No-Go）
