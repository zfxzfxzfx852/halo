## 正文

```markdown
## 背景：Agent 越来越强，但我们越来越看不清它在做什么

现在的 AI Agent 会自己调用工具、访问网络、读写文件。问题在于，这些动作对
开发者几乎是个黑盒：它具体调了什么、参数是什么、有没有危险操作，我们既看
不见，也很难在出事前拦住。

我不想再做一个 Agent 框架（这个赛道已经很卷），而是做了一个所有 Agent 都
能依赖的基础设施——[Halo](https://github.com/zfxzfxzfx852/halo)，一个本地
优先、开源的可观测与安全控制平面。这篇文章讲讲它的架构和几个真正踩过的坑。

## 整体架构

```
Agent ─► Halo 透明代理 ─► 策略 / 检测 / 沙箱 ─► 模型 / 工具
              │
              ▼
      事件存储 + 审计链 + WebSocket + 实时控制台
```

整体是一个静态编译的 Go 二进制：Web 控制台用 `go:embed` 内嵌，存储用纯 Go
实现的 SQLite（不依赖 CGO），前端是 React + TypeScript。一次策略决策大约
40 微秒，核心包测试覆盖率 70% 以上，CI 开启了 race 检测。

## 一、透明拦截：流式响应和 MCP 桥接

Halo 同时代理普通 JSON 和 **SSE 流式**响应。记录器会把请求/响应配对，并在
落库前脱敏敏感头。

MCP 这边，stdio 桥接是一个双向 JSON-RPC 中继，工具调用被转成事件并按 id
关联，这样即使经过流式传输，请求和响应也能对上。一个细节很关键：诊断日志
统一走 **stderr**，绝不会污染 stdio 上的 JSON-RPC 数据。

## 二、策略引擎：为什么要自己写 glob 匹配

最初用标准库的 `path.Match`，基本能用，直到遇到 `curl *` 这类规则——
`path.Match` 里 `*` 是不跨越 `/` 的，而命令里带 `https://...` 时就匹配不上。

后来换成自定义 glob：`*` 匹配任意字符（包括斜杠）、`?` 匹配单个字符，
模式编译后缓存。引擎按规则顺序评估、首条命中、支持 AND 条件，并在读写锁
保护下做原子热更新。

## 三、离线检测：被 HTML 转义坑了一次

检测完全离线运行，不依赖模型和外部调用，覆盖密钥、PII 和提示注入。

有个很隐蔽的 bug：Go 的 `json.Marshal` 会把 `<` 和 `>` 转义成
`\u003c` 和 `\u003e`，导致 `</system>` 这类注入特征匹配不到。解决办法是
扫描前先把这些转义还原成尖括号。另外用一份标注测试集来防止回归、控制误报。

## 四、人工审批和沙箱

当策略结果是「询问」时，调用不是被直接拒绝，而是被**挂起**。控制台通过
WebSocket 收到决策事件并弹出审批卡片，批准后调用继续，超时则默认拒绝。

沙箱目前是进程组驱动：独立进程组、可选降权、超时会杀掉整个进程组。
Docker、gVisor、Firecracker、WASM 都先定义成接口，后续接入不用动核心逻辑。

## 五、防篡改审计链

每个持久化事件都会追加到审计链：

```
hash = SHA256(prevHash + 序列化后的 event)
```

校验时从创世记录重新计算整条链，一旦对不上，会报出第一个不匹配的具体序号。
我专门直接改了数据库里的一行来测试，校验正确地返回 invalid 并定位到了记录。

## 先观察，后管控

接入方式和代码同样重要。Halo 默认是 **observe 模式**，只记录不阻断，你可以
先建立调用图谱和行为基线；等信任之后再切到 **guard 模式**让策略生效。这样
整个接入过程不会有打断现有工作流的风险。

## 上手

```bash
curl -fsSL https://raw.githubusercontent.com/zfxzfxzfx852/halo/main/scripts/install.sh | sh
halo init
halo
```

然后打开 `http://127.0.0.1:8787/console/` 就能看到控制台。
