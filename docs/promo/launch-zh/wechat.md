```
AI Agent 进网，安全治理的第一道关口应该建在哪？
```

```
本地优先的 Agent 安全控制平面：可观测、可管控、可审计
```

## 正文（适合公众号排版，段落短、小标题清晰）

```markdown
当 AI Agent 从「回答问题」走向「执行动作」，安全问题的性质就变了。

它会调用工具、访问网络、读写文件，甚至代替人完成业务操作。一旦遭遇提示
注入、账号被诱导，或者工具权限过大，风险就不再停留在文本层面，而是落到
真实的系统和数据上。与此同时，智能体进网监管趋严，企业对权限边界、数据
防泄漏和审计追溯的要求也在快速提高。

## 难点：默认是个黑盒

现实中最尴尬的是，Agent 做了什么往往看不见：调用链散落在各处，出了问题
难以复盘，更别说在危险操作发生前拦住。如果一上来就强管控，又容易误伤正常
流程，业务方根本不敢用。

## 思路：先观测，后管控

更稳妥的路径是分两步。

第一步，在 Agent 与模型/工具之间建立透明的观测层，不改动 Agent 代码。
每一次调用都被记录，通过实时事件流和调用图谱呈现，风险一目了然。这一步
只观察、不阻断，先把正常行为基线建立起来。

第二步，在看清楚的基础上启用策略：声明式的允许、拒绝和人工审批，高危
操作必须先确认，危险命令放进沙箱；对提示注入、密钥和个人信息做离线检测
与脱敏。

## 可审计，是合规的底线

所有事件通过哈希链串联，任何一条记录被篡改，校验时都能定位到具体位置；
会话可以完整回放，审计日志可导出。这对应了等保和内部风控对「操作可追溯、
完整性可验证」的基本要求。

## 本地优先，天然适配私有化

整套能力打包在单个二进制里，数据落在本地、默认零遥测，支持完全离线检测，
也能配合本地模型运行。对需要私有化部署、数据不出域的场景，这种形态部署
和运维成本都更低，也便于后续做国产环境适配。

## 结语

Agent 的安全治理，不是再加一道墙那么简单，而是让每一次调用都「看得见、
管得住、可追溯」。

相关实现已经以 MIT 协议开源（Halo），包含演示、文档和完整的信任边界
说明，有需要的团队可以直接参考或在其基础上构建。
```
